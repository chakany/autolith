#+TITLE: Structlisp Adoption Audit
#+DATE: 2026-08-14
#+STARTUP: content
#+OPTIONS: toc:nil num:nil

Autolith uses Structlisp when a complete integration removes meaningful
application source while preserving policy, locking, persistence, and public
projections. Structlisp is a first-party extensible library: missing reusable
mechanics belong there, with exhaustive structure tests, rather than in
Autolith wrappers.

* Dependency

Autolith pins Structlisp revision
=66bbfbe947b69f3105f71f5e4293637decc91746= through Qlot and Nix; ASDF
names the dependency without a revision. The Nix source hash is
=sha256-ax+mwi9opGFkycQjNNDJyLPUI11aOdTtljb4WDthUI4=.

Only required symbols are imported into the single =autolith= package. Runtime
containers remain internal. Durable records, rollback snapshots, and public
results retain portable lists and other established representations.

* Adopted structures

The complete adoption range from =f58c2f1= through =0194191= contains nine
application integrations. It changes =src= by 833 additions and 959 deletions,
for 126 fewer source lines. Tests change by 573 additions and 471 deletions,
for 102 more test lines, while =test-assert= forms fall from 3,633 to 3,630.
Generic mechanics and their exhaustive tests moved into Structlisp; Autolith
kept product boundaries and failure coverage.

** Transcript replay history

The transcript pager replaced duplicate circular arrays, indices, and counts
with count-bounded deques. Replay order, page boundaries, and public list
projections are unchanged. The integration removed five net source lines.

** Localgroup transport

Attachment packets, terminal input events, and terminal replay history now use
lock-confined deques with their existing overflow, close, wakeup, and
partial-front policies. The integration removed 28 net source lines and added
ten net test lines.

** Child activity trace

The newest-eight completed-tool list is now a count-bounded chronological
deque. Snapshots remain portable chronological lists under the existing lock.
The integration removed six net source lines.

** User-operation retention

Bounded durable user-operation context now uses a deque for count and character
weight mechanics while Autolith retains rendering, persistence, and context
selection policy. The integration removed seven net source lines and added nine
net test lines.

** Child steering

Steering and response-promotion queues now use deques, including selective and
mapped transfers added and tested in Structlisp. Autolith retains admission,
character budgets, cancellation, wakeups, exact-once promotion, and durable
projections. The integration removed 14 net source lines and added 25 net test
lines.

** Tool registry

The parallel presentation-order list and canonical-name hash index became one
ordered map. Canonical lookup, replacement position, runtime bindings, provider
schema order, child filtering, MCP reconciliation, and detached list
projections are unchanged. Structlisp gained predicate deletion. The integration
removed five net source lines and added 125 net boundary-test lines.

** Resource observations

The parallel alias hash, FIFO order list, repeated workspace-byte summation, and
copy/remove mechanics became a weighted FIFO cache. Autolith retains revision
authority, per-family limits, workspace-only UTF-8 byte eviction, locking,
persistence expiry, and edit authority. The complete pin and integration slice
removed seven net source lines, 45 net test lines, and four assertions after
redundant container tests moved to Structlisp.

** Deferred input

The durable later queue and controller projection became one stable priority
queue. Portable state forms, atomic persistence, cancellation, rescheduling,
wakeups, and controller policy remain in Autolith. The integration removed 20
net source lines and one net test line.

** Responsive input queues

Follow-ups, recalled input, pending submissions, and related transfer paths now
use deques. Structlisp gained copying, predicate search, selective transfers,
and mapped transfers with exhaustive mechanics coverage. Autolith retains
Shift-Tab policy, image-bearing input, durable FIFO restoration, wakeups, and
submission races. The complete slice removed 34 net source lines, 21 net test
lines, and four assertions.

* Evaluated and rejected integrations

The following candidates were checked against complete source, import,
projection, and test costs. They remain application code because the full
change was not materially negative.

- Workspace visible-line ranges :: Structlisp interval sets express merge and
  membership mechanics, but selective imports, inclusive to half-open
  conversion, formatting and elision projection, immutable snapshot handling,
  fixture changes, and missing boundary coverage produce about one to six more
  source lines and 30 to 60 more test lines.
- Context contributor registry :: An ordered map covers most registry
  operations. Exact-position rollback would justify a generic
  =ordered-map-insert-at= API, but the combined Structlisp and Autolith change
  is source-positive and strongly test-positive. Existing locking and detached
  list snapshots must remain.
- Numbered line window :: Structlisp gained atomic builder range appends and
  exhaustive callback, truncation, type, and rollback tests. The complete
  Autolith prototype removed only five net source lines and no tests, so it was
  reverted while the independent Structlisp improvement was retained.
- Provider form writer :: A bounded builder would replace only a small budget
  helper. Construction, finish, and condition translation erase the saving;
  rendering policy tests remain application-specific.
- Memory ranking :: A generic top-k operation saves only about eight to fifteen
  source lines. Autolith still owns scoring, deterministic tie policy, recall
  limits, and projections, while Structlisp would need a new mechanics suite.
- Terminal image history :: A bounded deque saves about three to eight source
  lines. Slot, search, and projection changes offset most of the insertion
  simplification.
- Provider projection tails :: Deques would replace O(1) list tail pointers but
  add conversions around list consumers, indexed reverse traversal, family
  projections, and tests. The complete change is neutral or positive.
- Command and model completion :: A sorted index adds synchronization and
  projection code around small, frequently rebuilt UI collections.

* Corrected performance investigations

These performance-related investigations require profiling; they are not
approved Structlisp integrations.

** JSON object determinism

=json-object= is an ordinary string-keyed hash table and =json-encode= delegates
to Yason, so current source has no object-key ordering contract. Current source
does not prove that decode and re-encode changes bytes, nor that object order
harms provider caching. An ordered representation would affect construction,
decoding, copying, durable reload compatibility, and encoding, not only one
constructor and encoder. If byte-stable JSON is required, first define and test
a canonical encoding policy, then measure any provider-cache benefit.

** Transcript history indexing

History paging scans every durable segment and retains the newest visible
records before the requested floor. Segment scans expose an end position, but
no reusable per-sequence index. A sequence-to-offset index alone cannot make
paging O(page): an implementation must include segment identity, visibility
filtering, validation, compaction and rotation updates, and either reverse
traversal or indexed visible page boundaries. Profile the path before choosing
a structure.

** Resource observation digest

No open digest optimization remains. Workspace revisions already use a keyed
digest of exact content, and matching checks URI and revision before the final
exact =string== comparison. The exact comparison preserves collision-safe
observation identity. The workspace observation cache also enforces a separate
16 MiB aggregate retained-byte limit, so the earlier 64 MiB comparison claim
was incorrect.

* Result

The reviewed range integrated the nine named structures that materially reduced
Autolith source and rejected the named plain substitutions after complete cost
accounting. Structlisp keeps the reusable mechanics and exhaustive tests;
Autolith keeps policy, locking, persistence, projections, and boundary tests.
The remaining JSON and history items require evidence and broader designs, not
a container swap.
