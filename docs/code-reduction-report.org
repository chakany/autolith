#+STARTUP: content

Audited at master =37c2f80= in a detached checkout, with 141 source files /
74,246 lines under =src/=+=server/=+=recovery/= and 72 test files / 77,418
lines containing 3,977 =test-assert= calls. Method: token-level
definition/reference analysis
with exact declaim baselines, identical-line and identical-after-rename
function comparison across file pairs, per-library imported-symbol usage
counts, and pattern sweeps over the test suite. Estimates are lines

** 1.2 The item-resource triplet is one protocol written three times

The strongest duplication cluster in the tree:
=src/resource/memory.lisp= (741), =src/resource/papercut.lisp= (646),
=src/resource/agenda.lisp= (511). Identical-line counts: memory<->
papercut 80, agenda<->papercut 47, agenda<->memory 45. Six functions in
memory/papercut are byte-identical after prefix rename
(=--identifier-unreserved-octet-p=, =--encode-identifier=,
=--decode-identifier=, =--malformed-item-identifier=, =--item-uri=,
=--read-result=), and five whole function families recur across all
three (=--find-observation-state=, =--normalize-operation=,
=--validate-operation-fields=, =--render-item=, =--read-result=).

=src/resource/protocol.lisp= (468) already defines the resource
protocol; what is missing is a second-level protocol for "collection
of identified items with revision-gated observations": canonical
=scheme:id/<percent-encoded>= URIs, observation registries with the
=*...-maximum-observations* 16= bound (declared separately in all
three files plus workspace-file), single-operation validation, and
item rendering. A =identified-item-resource= mixin with generic
functions for item lookup, rendering, and operation application would
collapse an estimated 500-700 lines and make the next resource type
(there will be one; papercut was the newest) a page instead of 650
lines.

** 1.3 Device authentication: the generic base arrived, two flows never migrated

=src/provider/rfc8628-device-authentication.lisp= (354) is a clean
generic RFC 8628 flow, and =nous/device-authentication.lisp= (a page)
subclasses it. But =src/provider/device-authentication.lisp= (647,
Codex) and =grok/device-authentication.lisp= predate it and still
carry their own polling loops, interval handling, and token exchange
(20+ identical lines with the rfc8628 file). Migrating Codex and Grok
onto the rfc8628 base the way nous already sits should remove several
hundred lines and one whole duplicated state machine.

** 1.4 Smaller clusters worth a pass

- =src/state/memories.lisp= <-> =src/state/papercuts.lisp=: 36
  identical lines; same append-only readable store shape
  (=--read-forms= is identical after rename, 8 more functions have the
  same shape). A shared append-only-store helper (or sexp-store
  extension, see 2.3) halves one of them.
- =src/provider/anthropic/client.lisp= <-> =openai-compatible.lisp=:
  37 identical lines translating portable items to role-message
  dialects; both grew the same helpers independently. A shared
  "chat-shaped translation" layer belongs next to the Responses codec
  (see 2.1).
- =src/application/commands.lisp= <-> =application/runtime.lisp=: 36
  identical lines, mostly presentation plumbing.
- =src/application/recovery-input-vault.lisp= <->
  =terminal/responsive-input.lisp=: 37 identical lines of pending-state
  form handling — the parser lives in responsive-input while its vault
  consumer re-declares shapes; one owner module would do.
- =tool-namespace-description= (=src/tools/registry.lisp:213=): a
  string-=cond= mapping namespace to description, far from where
  namespaces are registered. Registration should carry the
  description; the cond is a shadow table that must be edited in sync.

* 2. Belongs in existing lambda-symbolics libraries

Dependency hygiene is good: every dependency in the qlfile is used
(per-symbol import audit; no dead libraries, only a handful of unused
imported symbols). The gaps run the other way — code that should
have moved down when its library was extracted.

** 2.1 The provider engine belongs in cl-llm-provider-api

The library today is 887 lines of generics plus RLM budgets/views/
objects. The engine that makes those generics usable stayed in Autolith:

- SSE decoding with bounded lines/events and the inactivity deadline
  (=src/provider/client.lisp=, =sse-read-line= family).
- The bounded retry ladder with resample/backoff semantics
  (=provider--call-with-bounded-retries=, retry delays, retryable
  status/code tables).
- Credential redaction in streams and errors
  (=*provider-credential-redaction-marker*= machinery).
- The shared Responses wire codec (=src/provider/wire-protocol.lisp=,
  ~470 lines: function-name encoding, tool flattening, deferred
  namespaces, request assembly).
- The thin JSON layer (=src/core/json.lisp=, 94) and bounded
  character reads (=src/core/streams.lisp=, 193) these depend on.

None of this is Autolith-specific; all of it is what a second consumer
of cl-llm-provider-api would immediately need. Moving it relocates
roughly 2,000-2,500 lines and makes the library honest — right now it
exports a protocol nobody could implement a client with.

** 2.2 RFC 8628 rides along

=rfc8628-device-authentication.lisp= plus the =credential-manager= /
=credential-source= CLOS protocol from =src/provider/authentication.lisp=
are provider-generic and pair naturally with 2.1 (the OAuth refresh
loop is part of any serious provider client). The per-provider store
files (grok 212, fireworks 106, opencode 82, nous 388) stay; their
shared skeleton shrinks once the protocol lives downstream.

** 2.3 Versioned record validation belongs in sexp-store

Fourteen-plus files hand-roll the same trio: =X--form-p= (versioned
plist shape validation), =X--state-form= (render), =X--write= (atomic
snapshot with mode bits) — =state/later.lisp=, =agendas=, =updates=,
=plan=, =preferences=, =permissions=, =image-commits= (6 of them),
=identifier-migration= (5), =localgroup/handoff= (3),
=recovery-input-vault=, =conversation/store=, =task/child=. sexp-store
already owns =snapshot-read/write=; a declarative
"versioned record" layer (field specs + version set + migration hook)
would delete the majority of these validators — several hundred lines
of the most defect-prone code in the tree (three of this session's
past bugs were in exactly these validators).

* 3. Generic functionality worth a new library

** 3.1 localgroup: a tmux-shaped session layer (~4,600 lines)

=src/localgroup/= (protocol 327, runtime 788, terminal 536, client
811, handoff 965, checkpoint 22) plus =management/repl.lisp= (1,180)
implement: authenticated loopback control endpoints with token files,
terminal attach/relay with resize and take-over, detached process
handoff with supervised launch, and status/tell/kill CLI. Aside from a
handful of application hooks, nothing is Autolith-specific — this is
"tmux for a Lisp image" and is precisely the kind of extraction that
worked for sbcl-generations and sbcl-workers. Suggested shape:
=lambda-symbolics/cl-sessiond= with an application-facing protocol of
a dozen generics; Autolith keeps its hooks.

** 3.2 The conversation transcript store (~3,300 lines, longer term)

=src/conversation/store.lisp= implements append-only chunked readable
transcripts of Responses-style items with leases, family-private item
filtering, compaction records, and picker metadata. As
cl-llm-provider-api grows consumers, a portable transcript store
(=cl-transcript=) is the natural companion; the Autolith-specific
parts (picker previews, working-seconds) are a minority. Flagged as
direction, not a this-quarter extraction — it is entangled with
application/runtime today.

** 3.3 The responsive terminal stack (~8,100 lines, long term)

=src/terminal/= is a coherent non-fullscreen TUI: diff-rendered rows,
live region, prompt markers, syntax highlighting over colorlisp,
event handling over clinedi. It is the most distinctive UI in the
Lisp ecosystem right now and other agents/tools would use it. It is
also deeply tied to the application object; extraction cost is high.
Worth an interface-tightening pass now (application touches
=terminal-ui= through ~30 functions; get that to a protocol) so
extraction stays possible.

* 4. Change-detector and verbiage tests

Sweep results over =tests/=: 211 assertions =search=-ing literals of
25+ characters, 62 =string== comparisons against 40+ character
literals, 119 exact-length assertions. They divide into three kinds;
only one kind should exist.

** 4.1 Wire-contract pins — keep

Literal assertions on provider wire shapes (=grant-type=device_code=
URL encoding, =tools[0]= layouts, =prompt_cache_key= presence,
percent-encoded URIs) test real external contracts. Breaking them
means breaking a server. Keep, including the exact-length assertions
on wire =tools= arrays in provider tests.

** 4.2 Condition-prose pins — refactor mechanically

Dozens of tests assert error TEXT ("only while an agent turn is
active", "memory:relevant is read-only", "unavailable under this
authority context") because the conditions carry their distinction
only in prose. Each such test is a change-detector: rewording a
message fails it with zero behavior change. The fix is in src, not
tests: give conditions machine-readable discriminators (the
=image-commit-error-stage= keyword pattern already used in
image-commits is the house style) and assert those. The papercut
corpus shows the cost is real — wording changes have broken these
before.

** 4.3 Presentation-verbiage pins — delete or loosen (the "retarded" bucket)

The change-detector archetype from the Google testing-on-toilet piece:
tests that restate the implementation and fail on any edit.
Worst offenders by density: =tests/application-tests.lisp= (170
=search= literals), =tests/terminal-tests.lisp= (124),
=tests/self-tool-tests.lisp= (36).

Representative deletions/looseners:
- =(string= (terminal-ui-notice ui) "Interrupting request.")= asserted
  three separate times (application-tests 1103, 1107, 1812) — the
  behavior is "a notice is shown while interrupting"; the prose is
  incidental. One test asserting non-empty notice suffices.
- "◆ loaded skill: code-review" / "◆ skill already loaded:" glyph
  pins in skill-tool-tests — pins a bullet character.
- Tip-text and banner assertions (application-tests:448 =search
  "Tip: "= onward) — the startup banner is version-churn territory.
- =(= (length variants) 14)= in workspace-resource-tests:1065: a pure
  count mirror of the resource.edit schema. It has already been
  hand-bumped twice (12→14 in one session) without ever catching a
  bug; each new edit variant breaks it by design. Assert the variants
  the test actually cares about exist, not the total. (Authorship
  disclosure: the current form of this pin is mine.)
- Catalog mirrors in tests/tests.lisp (context window = 272000,
  compaction limit = 217600) restate =*model-context-windows*= —
  they fail exactly and only when the catalog table is edited, i.e.
  they test that the table is the table.

A reasonable cleanup target is deleting or loosening 100-150
assertions; the suite loses no bug-catching power and gains
significant refactoring freedom. Given 3,977 assertions total, this
is ~3% of the suite and probably a third of its false-failure rate,
judging by which tests this session's own refactors kept tripping.

** 4.4 Structural note

The house test style (mega-functions of sequential =test-assert=
calls) makes every verbiage pin block all later assertions in the same
function, which amplifies 4.2/4.3: one reworded message hides real
signal behind it. Splitting is out of scope here; deleting the pins is
the cheap 80%.

* 5. Reimplementations of mature Common Lisp libraries

Short list — the codebase is disciplined about dependencies, and
several apparent candidates are deliberate (the dependency-free test
harness is policy per AGENTS.md and should stay).

- RFC 3339 parsing/printing, hand-rolled in =src/core/time.lisp=
  (78 lines): =local-time= is the mature answer. Marginal call — the
  local code is small and tested — but every timestamp bug ever filed
  here would have been someone else's bug instead.
- Percent-encoding/decoding of item identifiers, hand-rolled twice
  (=resource/memory.lisp:119-160= and its byte-identical papercut
  twin): =quri= is already a dependency and exports
  =url-encode=/=url-decode= with an alphabet argument. ~70 lines,
  two copies, plus their tests.
- Hex rendering (=localgroup--hex-string=, protocol.lisp:84):
  ironclad, already a dependency, exports
  =byte-array-to-hex-string=. Ten lines, but it is the third
  private hex helper this tree has grown (api-key fingerprints and
  workspace identifiers format their own).
- =padded-base64url= (core wrapper over cl-base64): fine to keep;
  cl-base64's =:uri t= handles the alphabet, only padding is local.
- JSON, HTTP, TLS, URI, threading, image ops: yason/dexador/cl+ssl/
  quri/bordeaux-threads/opticl — all already used rather than
  reimplemented. No action.

* Priorities

1. Delete the 24 dead functions (owner pass for REPL-surface keepers)
   and the =tool-namespace-description= shadow table. Small, safe,
   immediate.
2. The item-resource protocol (1.2) — biggest single duplication,
   and the next resource type pays for the refactor by itself.
3. Migrate Codex/Grok device auth onto rfc8628 (1.3).
4. Test cleanup (4.3 deletions, 4.2 discriminator refactor) —
   directly reduces the false-failure tax on every future change.
5. Move the provider engine down into cl-llm-provider-api (2.1/2.2)
   — the largest strategic reduction, sized in thousands of lines,
   best done as its own project.
6. sexp-store versioned records (2.3), then cl-sessiond (3.1) when
   there is appetite for a new library.
