# Autolith 0.30.0

Autolith 0.30.0 makes structured mutations easier to review and turns `PROMPT` into a callable Lisp interface for primary and child work.

- Unify file, agenda, and memory mutation presentation behind one bounded, line-numbered, colored change viewer.
- Preserve exact revision preimages, semantic agenda and memory documents, applicable syntax highlighting, and honest structured fallback when an exact diff is unavailable.
- Add `(prompt CONTENT)` for ordinary primary input and `(prompt (read-file PATH))` for bounded computed UTF-8 prompts.
- Add `(prompt :to TARGET CONTENT)` to steer an existing visible running child by unique display name or job ID without spawning another child.
- Treat every explicit `:to` target as child routing, including a running child named `autolith`.
- Deliver child steering in FIFO order and reserve one response-promotion token for each accepted child prompt.
- Promote the first later durable nonblank verbal response into the primary window while leaving tools, reasoning, blank output, and primary conversation history untouched.
- Render promoted responses with a timestamped child header, Markdown body, and semantic xterm-256 color with a basic-color fallback.
- Harden response promotion and task presentation against concurrent consumption, terminal cleanup, stale listeners, replaced orchestrators, and overlapping reconnects.
- Document the callable prompt forms, steering behavior, response presentation, and unified mutation viewer.
