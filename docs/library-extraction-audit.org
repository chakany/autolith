#+TITLE: Autolith Library Extraction Report
#+STARTUP: content
#+OPTIONS: toc:nil num:nil

* Decision

Do not create another library merely to shrink Autolith. Extract only a
coherent protocol with a neutral API and independent tests. The reusable
terminal Markdown boundary is now shared as =cl-termdown=; future extractions
still require a concrete second consumer or immediate shelf-level reuse.

* Already Shared

- =clinedi= owns Unicode editing, completion selection, terminal geometry, and
  the scrollback-safe live region shared by Autolith and CCLSH.
- =cl-colorist= owns ANSI capability detection, color styles, and control
  sequence handling.
- =colorlisp= owns language detection and Tree-sitter highlighting.
- =cl-termdown= owns semantic spans, cell-aware columns, and incremental
  terminal Markdown rendering with ColorLisp code highlighting.
- =mcparen= owns MCP transport and protocol machinery.
- =sexp-store= owns safe readable snapshots and append-only S-expression logs.
- =sbcl-workers= and =clifff= also keep worker and indexed-search machinery
  outside the agent application.

* Viable Future Extractions

** Request-local context engine

Priority: first, only after a second agent or shell feature needs it.

=src/agent/context.lisp= has a general core: named contributors, stacking,
deduplication, priorities, bounded advice budgets, =:turn= and
=:next-request= lifetimes, and payload-free diagnostics. A neutral library
could accept caller-owned request and conversation keys, then return selected
contributions and lifecycle receipts.

Autolith must keep memory ranking, Skill selection, project adaptations,
self-review policy, provider-request construction, and all built-in advice.
Without another consumer this would be a premature abstract harness, so it
should remain in-tree for now.

** =sexp-store/schema= optional system

Priority: second, only if another library needs versioned native configuration.

The repeated safe property-list validation and migration patterns in
=src/state/records.lisp= and =src/configuration/= could become a small optional
=sexp-store= system. Its scope would be exact required and optional fields,
version dispatch, typed validators, and explicit migrations over data already
read by =sexp-store=.

It should not become an object mapper or absorb Autolith's configuration
policy. Until there is a second schema consumer, the local validation remains
clearer.

* Keep In Autolith

The provider and conversation model, tool registry, Skills, task scheduler,
self-modification and recovery, memories and agendas, image attachments, and
release service are product semantics. They have no clean independent API yet.
Extracting them now would move complexity without buying reuse.

* Extraction Gate

An extraction proceeds only when it has a second consumer, a small API free of
Autolith classes, its own package and ASDF system, focused failure-path tests,
and a narrow adapter left here. Pin the dependency as inspectable source and
make release builds bundle it without requiring a global installation.
