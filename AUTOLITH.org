#+title: Autolith project adaptations

* Purpose

This voluntary file records reusable ways Autolith adapts itself to this
project. It supplements AGENTS.md and never overrides repository policy, user
instructions, or capability boundaries. It contains documentation, not
executable Lisp.

* Project profile

Record project-specific tools, workflows, and recurring friction only when they

* Active adaptations

For each adaptation, record its problem, behavior, scope and location,
verification, and removal condition. State whether it is tracked project work,
a user-local init.lisp change, or a private image commit.

** Modified Enter terminal compatibility

- Problem: the active-turn cancellation change disabled Kitty CSI-u reporting to
  preserve plain Escape, leaving Alacritty unable to distinguish Shift-Enter or
  Ctrl-Enter from ordinary submission. Some Ctrl-Shift-V paste paths also arrive
  without bracketed-paste markers or a literal Ctrl-V byte, so embedded newlines
  were interpreted as submission.
- Behavior: terminal startup again enables Kitty CSI-u and xterm
  modifyOtherKeys. A narrow Autolith decoder handles supported Kitty reports for
  Escape, Enter, Tab, Shift-Tab, and Backspace before delegating all other input
  to Clinedi. It collects bounded literal Ctrl-V and raw multiline byte bursts as
  paste events, while buffering ordinary multi-key bursts for normal decoding.
  Partial protocol activation performs balanced best-effort cleanup. Terminal mode
  detection checks the input file descriptor's POSIX TTY status before inspecting
  termios, so stopping and restarting the UI for line-oriented secret prompts
  remains interactive even when the Lisp stream wrapper reports noninteractive.
- Scope and location: tracked project work in =src/terminal/input.lisp=,
  =src/terminal/protocol.lisp=, =src/terminal/stream.lisp=, and
  =src/localgroup/terminal.lisp=.
- Verification: modified Enter, enhanced Tab and Shift-Tab, legacy input,
  bracketed, literal Ctrl-V, raw string-stream, and OS-pipe multiline paste,
  ordinary buffered keys, protocol ordering, follow-up cycling, descriptor-backed
  terminal restart, and cleanup regressions pass in focused checks. The complete
  repository check still reaches the environment's existing workspace-write
  failure at =tests/tool-tests.lisp:591=.
- Removal condition: Clinedi natively decodes the bare Kitty control reports and
  terminals reliably bracket every paste path, so Autolith can remove its
  compatibility reader without losing Escape or multiline paste semantics.

** Authenticated local session control

- Problem: long-running Autolith processes exposed no reliable external view of
  session identity, strict idleness, queued work, cancellation, or live child
  jobs. Operators therefore could not safely inspect, message, attach to, pause,
  or stop another local session, and releasing a foreground terminal risked
  losing accepted input or conversation ownership.
- Behavior: each process publishes a private authenticated loopback endpoint
  with strict idle-state reporting and bounded length-prefixed local control.
  Read-only and controlling terminal relays preserve ordered, bounded output and
  support observation and live take-over. Foreground
  detach and take-over use an atomic, supervised process handoff that preserves
  the localgroup identity, capability, durable conversation, permissions, and
  composer draft. Cancellation positively stops the replacement process group
  before the old process restores its conversation lease.
- Scope and location: tracked project work in =src/localgroup/=,
  =src/application/=, =src/startup/main.lisp=, and the stable-launcher command
  dispatch in =src/launcher/main.lisp=.
- Verification: protocol, privacy, status, command, relay, queue-admission,
  snapshot, lease-transfer, cancellation-interleaving, fresh-conversation, and
  supervised process-group regressions pass within the complete 3,227-test
  repository check.
- Removal condition: the supported runtime gains an equivalent authenticated
  local process/session protocol and atomic foreground handoff with the same
  state, ownership, and rollback guarantees.

** Conservative line-aware fs.edit fallback

- Problem: 4,552 historical =fs.edit= calls included 773 exact old-text misses.
  In the longest current session, multiline edits failed at 30-41 percent by
  size band, and 122 misses were followed by retries whose lines differed only
  at their leading indentation.
- Behavior: =fs.edit= still prefers exact replacement. On an exact miss it may
  normalize one unique multiline LF/CRLF match or rebase one unique uniform
  leading-space shift when =new-text= retains an unchanged boundary line.
  Ambiguous, mixed-EOL, tabbed, nonuniform, or unanchored cases remain unchanged
  and return an exact bounded near match for retry.
- Scope and location: tracked project work in =src/tools/workspace-edit.lisp=,
  =src/tools/workspace.lisp=, and the =fs.edit= schema and guide.
- Verification: focused workspace-tool tests pass, the repository check passes
  3,010 tests, active and recovery images rebuild successfully, and replay
  analysis found that 66 of 125 line-trim-equivalent retry pairs passed the
  uniform-shift, boundary-anchor, and rendering gates.
- Removal condition: the provider supplies a native structured patch protocol
  with equal or stronger uniqueness, line-ending, and indentation safeguards.

** Revision-gated workspace, agenda, and memory resources

- Problem: exact-text editing requires models to reproduce existing source,
  indentation, and line endings, causing avoidable retries and output token use.
  Independent file or agenda calls could also mutate content after inspection.
- Behavior: =resource.read= establishes transient conversation-local observations.
  For =workspace:= files it retains an exact bounded snapshot and only lines fully
  shown to the model; =resource.edit= applies validated original-line operations,
  rejects unseen or stale content, serializes native filesystem mutations,
  preserves uniform line endings and final-newline state, and atomically replaces
  the file. For =agenda:current= it returns the complete readable current agenda,
  retains an exact snapshot including empty state, and applies exactly one
  revision-gated add, update, or remove under the same recursive lock as legacy
  agenda tools. Agenda revisions address exact snapshots, so an alias is stale
  while content differs and valid again if the exact snapshot returns. Agenda
  URIs cannot resolve another workspace or the raw state file, task child agents
  cannot resolve them, and aliases cannot cross conversations or workspace
  changes. The agenda lock serializes same-process Autolith operations only and
  does not provide interprocess safety. =memory:= resources expose the relevant,
  workspace, and global collections plus exact active stable IDs through canonical
  =memory:id/<percent-encoded-stable-id>= URIs using existing scope rules. This
  namespace supports reserved collection names and arbitrary valid persisted IDs;
  direct item URIs remain compatible for non-reserved IDs. They return complete
  metadata, canonical item URIs, and excerpts or one full memory, retain exact
  snapshots including empty collections, deny task child agents, and never expose
  =memories.sexp=. Relevant and workspace snapshots include the canonical current
  workspace identity, while global snapshots remain workspace-independent. The
  relevant collection is read-only; workspace and global collection revisions
  each accept one complete create, while exact item revisions accept one complete
  replacement or tombstone. Every memory operation validates before persistence,
  rechecks the exact snapshot, attributes writes to the source conversation, and
  appends under the recursive process-local memory lock. This lock does not
  provide interprocess CAS. Existing
  =fs.edit=, =agenda.*=, and =memory.*= tools stay available as compatibility
  paths.
- Scope and location: tracked project work in =src/resource/=,
  =src/state/agendas.lisp=, =src/state/memories.lisp=,
  =src/conversation/store.lisp=, =src/tools/defaults.lisp=, and the resource
  schemas, prompt, specification,
  guide, and regressions.
- Verification: workspace URI confinement, observation isolation and expiry,
  visible-range gating, original-snapshot multi-operation edits, stale and
  protected paths, bounded UTF-8 snapshots, empty files, atomic publish failures,
  line endings, plus agenda empty and complete reads, revisions, confinement,
  add/update/remove, memory links, shared locking, and legacy compatibility pass.
  Memory collection scopes, exact IDs, empty and missing states, child denial,
  typed mixed observation retention, schemas, and existing memory tools also pass
  within the complete 3,559-test repository check.
- Removal condition: a provider-native editing protocol supplies the same exact
  revision, visibility, authority, atomicity, and recovery guarantees with lower
  harness complexity.

** Caller-selected shell runtimes and resilient output decoding

- Problem: long deployment commands were silently capped at ten minutes even
  when the user requested more time, while arbitrary generated-file bytes in
  command output could raise a UTF-8 decoding error and discard the exit status.
- Behavior: =shell.run= keeps its 60-second default but accepts any positive
  requested timeout without a product maximum. The sandbox still enforces the
  selected deadline and bounded output. Invalid encoded bytes are replaced at
  the command-sandbox boundary so status and surrounding diagnostics survive.
- Scope and location: tracked project work in =src/tools/workspace.lisp=, the
  pinned =cl-exec-sandbox= integration, the shell schema, specification, guide,
  and workspace-tool regressions.
- Verification: a requested 900-second timeout is retained, invalid UTF-8 shell
  output completes with replacement characters and its exit status, truncation
  remains bounded, and the complete 3,567-test repository check passes.
- Removal condition: the command sandbox dependency natively captures bounded
  arbitrary-byte output with replacement decoding and exposes caller-selected
  deadlines without an Autolith compatibility layer.

** Unlimited default child runtimes

- Problem: child agents were terminated after a fixed 30-minute wall-clock cap,
  discarding their live context and often leaving useful repository work without
  a terminal handoff.
- Behavior: task jobs have no runtime deadline by default. A positive
  =AUTOLITH_TASK_MAX_RUNTIME_MS= remains an operator opt-in to the existing shared
  deadline monitor. User, parent, descendant, shutdown, and active-turn
  cancellation continue to interrupt live work, while progress and terminal
  retention remain bounded.
- Scope and location: tracked project work in =src/task/state.lisp=, task runtime
  tests, the specification, and the guide.
- Verification: the default orchestrator has no deadline or monitor, a positive
  1,000-millisecond override still aborts a real stalled tool call with one
  durable terminal result, and the complete repository check passes.
- Removal condition: child providers support reliable resumable handoff at
  arbitrary forced deadlines without losing in-progress context or work.

** Actionable public Nix smoke annotations

- Problem: unauthenticated GitHub Actions logs were unavailable, and generic
  check annotations hid the persistent macOS first-run failure.
- Behavior: the Nix smoke step emits bounded stderr, stdout, exit status, and
  specific missing-artifact or missing-marker failures as check annotations.
- Scope and location: tracked project work in =.github/workflows/nix.yml=.
- Verification: run 30700246262 exposed the Darwin terminal-mode failure and
  its complete first-run phase output through the public annotations API.
- Removal condition: authenticated logs become reliably available or the Nix
  smoke path gains equivalent structured diagnostics elsewhere.

** Bounded release-host container builds

- Problem: repository checks inside release-builder containers repeatedly stopped
  producing output and remained alive indefinitely. The v0.23.2 container was
  still blocked in =script/check.lisp= after 40 minutes, preventing both v0.23.2
  and v0.23.3 archive publication even though the updater and server had already
  activated v0.23.2.
- Behavior: each managed release container has a unique name and a generous
  30-minute deadline. Failure or timeout prints bounded process and log
  diagnostics, then force-removes the complete container before the polling loop
  retries. The deadline is configurable with
  =AUTOLITH_RELEASE_CONTAINER_TIMEOUT_SECONDS=.
- Scope and location: tracked project work in =server/release-builder.lisp= and
  release-server regressions.
- Verification: timeout command construction, managed naming, structured failure,
  diagnostics, and forced cleanup pass within the complete 3,251-test repository
  check. The stuck v0.23.2 container was manually stopped before deployment.
- Removal condition: the release build moves to an execution boundary with native
  bounded runtime, complete descendant cleanup, and equivalent diagnostics.

** Extracted runtime library boundaries

- Problem: Autolith carried duplicate implementations for compact identifiers,
  restricted native configuration parsing, retained generations, child-job
  scheduling, and macOS command-policy translation.
- Behavior: pinned =idsmall=, =sexp-config=, =sbcl-generations=, =cl-jobpond=,
  and =cl-exec-sandbox= now own those reusable mechanics. Autolith retains its
  product-specific migration, validation, provenance, atomic state, authority,
  cancellation, and output policies. Two narrow compatibility adapters preserve
  standard keyword-to-string reader boundaries and publish task pool limits under
  the library's worker lock.
- Scope and location: tracked project work in =src/conversation/=,
  =src/configuration/native-source.lisp=, =src/mcp/=, =src/skills/=,
  =src/state/generations.lisp=, =src/task/=, =src/tools/workspace.lisp=,
  dependency locks, Nix packaging, architecture documentation, and regressions.
- Verification: parser adjacency, checkpoint fork detachment, concurrent hurry-up
  admission and policy updates, invalid UTF-8 shell output, dependency builds,
  and the complete 3,582-test repository check pass.
- Removal condition: =sexp-config= accepts standard terminating-macro boundaries
  directly and =cl-jobpond= exposes one public atomic pool-policy update operation;
  remove the corresponding Autolith adapters independently when each condition is
  met.
